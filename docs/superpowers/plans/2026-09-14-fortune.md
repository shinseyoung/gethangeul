# Korean Name Fortune Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fifth room at `/{lang}/fortune` that takes a name and a birthday and gives back which of the twelve zodiac animals the visitor is, four fortunes on meters, and a lucky colour, number and Korean dish.

**Architecture:** The birthday is calculated, not hashed — the year gives the zodiac animal (turning at Seollal, from a hardcoded table of lunar new year dates), the month and day give the season. The four fortunes combine the animal, the season and the name's own five traits, so two people born the same day still read differently. The card reuses the shell, meters and share hook the other rooms already have.

**Tech Stack:** React 19, TypeScript, Zustand, Tailwind 3, Vite 8. No test framework: checks are plain-TS scripts bundled by rolldown and run through `npm run check`.

**Spec:** [`docs/superpowers/specs/2026-09-14-fortune-design.md`](../specs/2026-09-14-fortune-design.md)

## Global Constraints

- **No randomness anywhere.** `Math.random`, `Date.now`, any hash-of-time are forbidden. A shared card has to reproduce, and a fortune that changes when you reload is a fortune nobody believes twice.
- **No new dependencies.** No lunar-calendar library — see Task 1.
- **Verification is `npm run check` and `npm run build`**, both passing before any commit. Assertions use the `ok(label, condition, detail?)` helper, in a new `scripts/fortune.check.ts` registered in the array in `scripts/check.mjs`, ending with the same `failures > 0 → process.exit(1)` block and one `console.log('...checks passed')`.
- **Locale keys ship in all four languages.** `en` and `ko` written properly; `vi` and `th` take the English verbatim, the standing decision since the syllable dictionary.
- **Copy register — this is a change from what the site has been doing.** Write the way people talk about this stuff now: short, spoken, no translationese, no literary flourish. The Korean especially: the existing K-Drama copy leans old and writerly ("뽀얗게 기억됩니다", "얄밉죠", "판이 다시 짜입니다") and that is the register to move away from. Say it like a person texting a friend about their 띠, not like a columnist. **No slang with a shelf life** — 유행어 dates fast and this copy is not getting rewritten every season.
- **Do not touch** `src/utils/nameTraits.ts`, `src/utils/strokes.ts`, `src/data/nameDatabase.ts`, `src/data/syllableDatabase.ts`, or anything in the K-Drama or match rooms.
- **House comment voice:** comments explain *why* a surprising decision was made, in prose. Never restate the code.

```ts
import { SEOLLAL } from '../data/seollal';

/**
 * Which animal a birthday belongs to, and which season it fell in.
 *
 * Both are facts a visitor can look up and find we agree with, which is the
 * whole reason the birthday is calculated rather than hashed. A hash would work
 * and nobody could tell — and the room would have nothing to show and nothing
 * to answer with, which is not how anything else on this site behaves.
 */

export type Animal =
  | 'rat' | 'ox' | 'tiger' | 'rabbit' | 'dragon' | 'snake'
  | 'horse' | 'goat' | 'monkey' | 'rooster' | 'dog' | 'pig';

/** The traditional order. 1900 was a rat year, and every twelfth since. */
export const ANIMALS = [
  'rat', 'ox', 'tiger', 'rabbit', 'dragon', 'snake',
  'horse', 'goat', 'monkey', 'rooster', 'dog', 'pig',
] as const;

export type Season = 'spring' | 'summer' | 'autumn' | 'winter';

export interface Reading {
  animal: Animal;
  season: Season;
  /** the zodiac year the birthday belongs to, which is not always its calendar year */
  zodiacYear: number;
}

const FIRST = 1920;
const LAST = 2044;

/** Parsed as UTC so a visitor's own timezone cannot move their birthday a day. */
function parse(iso: string): Date | null {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(iso)) return null;
  const d = new Date(`${iso}T00:00:00Z`);
  if (Number.isNaN(d.getTime())) return null;
  // Date rolls 2001-02-30 forward to March rather than rejecting it
  return d.toISOString().slice(0, 10) === iso ? d : null;
}

function seasonOf(month: number): Season {
  if (month >= 3 && month <= 5) return 'spring';
  if (month >= 6 && month <= 8) return 'summer';
  if (month >= 9 && month <= 11) return 'autumn';
  return 'winter';
}

export function readBirthday(iso: string): Reading | null {
  const date = parse(iso);
  if (!date) return null;

  const year = date.getUTCFullYear();
  if (year < FIRST || year > LAST) return null;

  const seollal = parse(SEOLLAL[year]);
  if (!seollal) return null;

  // born before this year's Seollal, so the zodiac year is still the last one
  const zodiacYear = date < seollal ? year - 1 : year;
  if (zodiacYear < FIRST - 1) return null;

  // 1900 was a rat year, so the offset from it gives the animal
  const animal = ANIMALS[(((zodiacYear - 1900) % 12) + 12) % 12];

  return { animal, season: seasonOf(date.getUTCMonth() + 1), zodiacYear };
}
```

ok('the lucky number is a single digit',
  all.every((f) => Number.isInteger(f.number) && f.number >= 0 && f.number <= 9));

Create `src/utils/fortune.ts`. The shape:

```ts
import { readName } from './nameTraits';
import { strokesOf } from './strokes';
import { readBirthday, type Animal, type Reading, type Season } from './zodiac';

/**
 * For fun, and the card says so — which is not a disclaimer bolted on the end
 * but the reason the room can exist at all.
 *
 * Three inputs, all of them the visitor's own: the animal their birth year
 * belongs to, the season they were born in, and what their name sounds like.
 * The third is what stops this being a birthday lookup with a name field
 * attached — two people born the same day read differently, which is the only
 * honest way a name can matter here.
 */

export type Luck = 'love' | 'luck' | 'work' | 'people';
export const LUCKS = ['love', 'luck', 'work', 'people'] as const;

export type Colour = 'blue' | 'red' | 'yellow' | 'white' | 'black';

/**
 * Each animal leans on two of the four lucks, and carries its 오방색.
 *
 * The colours are not invented. The twelve branches group into five elements
 * and each element has a direction and a colour: 인묘 wood/east/blue,
 * 사오 fire/south/red, 신유 metal/west/white, 해자 water/north/black, and
 * 진술축미 earth/centre/yellow. A visitor who looks this up finds we agree,
 * which is the same promise the zodiac year makes.
 *
 * The lean pairs are spread so each of the six possible pairs is used exactly
 * twice. That discipline is not decoration — the K-Drama room shipped twice
 * with a skewed distribution because one axis was fed by more options than the
 * others, and this is the same failure waiting to happen.
 */
const ANIMAL_LEAN: Record<Animal, { lifts: [Luck, Luck]; colour: Colour }> = {
  rat:     { lifts: ['luck', 'work'],    colour: 'black' },
  ox:      { lifts: ['work', 'people'],  colour: 'yellow' },
  tiger:   { lifts: ['love', 'work'],    colour: 'blue' },
  rabbit:  { lifts: ['love', 'people'],  colour: 'blue' },
  dragon:  { lifts: ['luck', 'people'],  colour: 'yellow' },
  snake:   { lifts: ['love', 'luck'],    colour: 'red' },
  horse:   { lifts: ['love', 'luck'],    colour: 'red' },
  goat:    { lifts: ['love', 'people'],  colour: 'yellow' },
  monkey:  { lifts: ['luck', 'work'],    colour: 'white' },
  rooster: { lifts: ['work', 'people'],  colour: 'white' },
  dog:     { lifts: ['love', 'work'],    colour: 'yellow' },
  pig:     { lifts: ['luck', 'people'],  colour: 'black' },
};

/** Each season leans on two, using four of the six pairs. */
const SEASON_LEAN: Record<Season, [Luck, Luck]> = {
  spring: ['love', 'people'],
  summer: ['luck', 'people'],
  autumn: ['work', 'luck'],
  winter: ['work', 'love'],
};

/**
 * Never nil and never full. A card that tells someone their love life is zero
 * has stopped being for fun, and a hundred leaves nowhere to go.
 */
const FLOOR = 15;
const CEILING = 90;
```

`tell(hangulName, iso)` returns `null` if either `readBirthday` or `readName` returns null. Otherwise, for each of the four lucks, start from a mid-scale base, add for an animal lean, add for a season lean, and add a contribution derived from the name's five traits — map each luck to the trait that belongs with it (`love` to `cute`, `luck` to `uncommon`, `work` to `refined`, `people` to `friendly`), scaled down so the birthday still leads. Clamp to `FLOOR`–`CEILING` and round once.

The lucky number is `strokesOf(name)` summed, mod 10. The colour is the animal's. The dish is the season.

Tune the weights so the assertions in Step 1 hold — in particular that each luck uses at least three of the five buckets across the sample. If one is flat, its animal and season leans are cancelling; check that the twelve animals do not all lean on the same pair.

## Deliberately not built

- **Real 사주.** Needs the hour, a solar-term table, and claims this site should not make.
- **A lunar calendar dependency.** 125 rows beat a library that can drift.
- **Daily or monthly fortunes.** They need a clock, and a clock makes the shared card stop matching the link.
- **A custom date picker.** `<input type="date">` already knows every locale's ordering.
